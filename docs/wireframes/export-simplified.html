Simpler USB export

Today there are three ways into an export and it asks ten technical questions on every run. The proposal: one “Sticks” button in the header. It opens one view where you pick a stick and tick its playlists; Sync shows one review in plain language, then writes. Everything else becomes a setting with a safe default: Settings › Export for how reks writes sticks, and the stick itself for which players it must work on. Track problems (missing or unplayable files) never block: those tracks are left out, counted, and fixable from the review.

Status: proposal, 2026-11-05. Replaces the export wizard’s Stick, Playlists and Options steps (src/components/ExportWizard.tsx, Phase 2 task 10) and merges the header’s Export button into the Devices view (AppHeader.tsx, DevicesDialog.tsx). Decision: D42 in docs/decisions.md (proposed).

1

Track problems never block. A missing, unreadable or unsupported file only leaves that track out; the rest is written. Replaces “Must be fixed first” + “Warnings” + the separate “Convert for older players” section. Each fix replans automatically; no “Plan again” button. Still blocking (whole stick can’t be written): unsupported file system, not enough space, a bad stick path (a reks bug).

2

Missing tracks, one row each: Artist – Title, the playlists on this stick that contain it, and the last known path. Find files… is the existing find-missing-files flow; afterwards the plan is rebuilt and found tracks go back in. Keep as it is (leave them out this time, keep them in the playlists) is the default.

3

Smart playlists: the row says “in a smart playlist: left out” and has no checkbox, because the track matches the playlist’s rule; removing it would not stick.

4

Remove from playlists removes the ticked tracks only from the library playlists ticked for this stick, never from others or the library. Confirm first (“Remove 11 tracks from 3 playlists? The tracks stay in your library.”), then the plan is rebuilt.

5

Unsupported formats: the same card with Convert… in place of Find files….

6

Nothing is left out silently. The primary button counts it (“Export 412 of 424 tracks”), and the report repeats it.

7

Missing analysis follows Settings › Export, default “Export with approximate analysis”: the tracks go on the stick with a generated waveform and beatgrid. The card says so; Analyse now runs the full analysis first.

8

History guard (D23), same rules, fewer words. Un-imported sessions show Import now (primary) / Back up and continue / More ▾ → Discard… with the existing confirm. After choosing, it collapses to a ✓ line.

10

Keep as it is on every warning card, and Keep all as they are at the top. It changes nothing: the card collapses to a ✓ line (“12 missing tracks left out, still in your playlists”). Export is never blocked by these cards, so the button is acknowledgement and tidying, not a gate.

9

OneLibrary removal (setting turned off, stick has exportLibrary.db) is one more card here with its existing checkbox confirm; unchanged behaviour.

  • Writing and Report merge into one step; the dialog title stays, only the body changes.
  • The four phases (history backup → copy → library → validate) show as a checklist line, so the user knows the stick is checked.
  • Eject is the primary button when the export succeeded: that is the next thing every DJ does. On problems, the primary is “Back to review”.

8. What changes in the code

Rust (business logic stays there)

  • reks-core settings: export keys for analysis source, missing analysis (generate | skip, default generate), artwork, clean-up, dividers, active loops, OneLibrary. Migration seeds them from the current defaults; experimental ones off for a fresh library.
  • export_default_options builds ExportOptions from settings + the device’s target. history is always backUp unless the guard picks otherwise.
  • skip_unsupported is removed. Per-track problems (SourceMissing, SourceUnreadable, Unsupported; plan/mod.rs ~686) always become one grouped Warning::Skipped with track ids, per reason. Still blocking: file system, space, BadPath.
  • New command: remove a list of track ids from a list of playlist ids, reusing the existing removeEntries playlist edit. Smart playlists are refused (the rule would bring the track back).
  • DryRun gains a summary (playlists changed, tracks/bytes to copy, free after) and issues as { kind, title, detail, actions: [...] }, a discriminated union worded in Rust.

UI

  • AppHeader: the “Export to USB…” button goes; the USB icon becomes “Sticks” with a plugged-in count, replaced by a single “Sync <name>” button (with ▾) when exactly one known stick is plugged in.
  • DevicesDialog becomes the Sticks view: stick cards (status, Eject, Sync), and the picked stick’s “Plays on” and playlist ticks. Its footer “Export to USB…” and “Edit and sync…” go.
  • EXPORT_STEPS: review → writing → done. DeviceStep, PlaylistsStep and OptionsStep are deleted; openExportWizard(mountPoint) always opens at Review.
  • New settings/ExportSettings.tsx tab.
  • Review: IssueCard (rows with checkboxes, actions), SummaryTiles, settings chip row; file lists behind Disclosure. Primary button counts tracks (“Export 412 of 424 tracks”).
  • Docs: new decision (proposed), phase-2.md task 10 rule on blocking problems, docs/ui.md, stick-profiles.md. Tests: ExportWizard.test.tsx, DevicesDialog.test.tsx, SettingsDialog.test.tsx.
