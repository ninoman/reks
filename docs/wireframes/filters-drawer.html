Filters drawer: one view

Today the drawer has a fixed form (Genre, Key, BPM…) and, behind Advanced, a separate rule builder ANDed with it; Save as smart playlist keeps only the Advanced rows. This merges both into one query: the main fields are there from the start, more can be added, everything is AND until you ask for OR, and a query can be kept as a saved filter or a smart playlist.

Revision 3 (concept A chosen)

  • My Tags: one row per tag category, each "any of / all of / none of" within the category, rows ANDed like any other field. Only the first category is a default row; the others come from Add filter. A field appears once per level; repeats only happen inside OR groups.
  • Added rows go next to the rows that filter, above the unused default rows.
  • No track count and no summary line in the drawer. The table already shows the count and its empty state; the rows themselves are the readable query (see "Why no summary line" below).
  • Saved filters: a picker at the top of the drawer to load, update and manage named filters; one Save… asks "saved filter or smart playlist".
  • Everything here is in the first cut: value search, Pause, saved filters and the toolbar quick-pick (S4).
  • Last played is "never" or "since a date"; no relative "last N days" filter. Today's bar options (last 30 / 90 / 365 days) go away.
  • Concepts B (chips) and C (query rows) are dropped.

Principles

An empty field filters nothingDefault fields show "Any". Setting a value turns the row on (outline, filled dot). No enable step, no Apply.
AND by default, OR where you need itOR within a field is multi-select (key 8A or 9A). OR across fields is Or… on a row, or a click on the connector.
The table is the feedbackThe drawer doesn't repeat the count; edits apply after a short pause and the table updates in place.
Keep what you useSave the drawer as a filter you load in one click, or as a smart playlist in the tree. What you see is what you save.
Try things without losing themPause a row, Exclude it, Undo after Clear all or after loading a saved filter over your edits.

Saved filters

A saved filter is a named drawer you load in one click. It narrows whatever you're looking at (the collection or the playlist chosen in the tree), stays editable, and lives in the Filters drawer, not in the playlist tree or on USB sticks. A smart playlist is the other way to keep a query: a list of its own, in the tree, exported as a fixed list.

Why no summary line

Today's builder already has one (summarize in src/store/ruleTree.ts), and it is correct, but it reads badly as soon as the query isn't a plain AND list. From its own tests:

Has tag Peak or Deep · not in playlist Warm-up · BPM is 120–128 (Has tag Peak or genre is House) · none of (in playlist Warm-up)

With tag categories, "all of" and longer lists it only gets longer, and in a 300px drawer it would repeat, in worse words, what the rows right below it already say. So the drawer drops it. It stays where the rows aren't visible: the saved-filter tooltip (S1) and the Filters button's tooltip, capped at one line with "…".

Behaviour

Query

  • One draft tree (GroupDraft) holds everything; the old FilterState form goes away. The playlist chosen in the tree stays outside, as today, and the drawer narrows it.
  • Root level is all. Empty, unfinished and paused rows are left out by toRule; so is an empty group (an empty "any" would match nothing).
  • One row per field per level; tag categories count as separate fields. Repeats only inside OR groups. A default field used anywhere in the query shows no extra empty row.
  • Order: an added row goes after the last row that filters on its level, above the unused defaults. Default rows keep their place when set.
  • Finished edits re-query after the existing 50 ms pause, only if the rule changed.
  • Clear all: empties default fields, removes added rows and groups, unloads a saved filter; one Undo toast.
  • On/off switch, Filters badge and both Save targets use the same tree.

Fields

  • Lists (Genre, Key, Colour, Playlist): any of / none of. Tag category: any of / all of / none of.
  • Numbers (BPM, Plays): min–max, either side optional. Rating: at least / exactly / at most.
  • Last played: never / since a date (Exclude: "not played since"). File: missing / present.
  • Default fields: BPM, Key, Genre, Rating and the first My Tags category; user-editable, stored with the other settings.
  • Quick paths stay: "Filter by tag X" fills that tag's category row; "Show tracks not in this playlist" adds a Playlist row.

Model and storage

  • Tag category any → TagAny; all → all group of one-tag TagAnys; none → TagAny with not. No core change.
  • Genre / Colour "any of" → any group of single filters. Rating at most / exactly → RatingMin with not / combined.
  • core Saved filters: a filter_preset table (name, position, rule JSON RuleNode, timestamps), a migration and create / rename / update / delete / reorder ops, same reference rules as smart lists. Kept in the library, so they survive a reinstall and travel with it.

Decided (2026-10-23)

  • Concept A. One row per tag category; only the first category is a default row.
  • Added rows sit next to the rows that filter, above the unused defaults.
  • First cut has everything: value search in Add filter, Pause, saved filters, the toolbar quick-pick.
  • No "played in the last N days"; Last played is never / since a date.
  • No track count or summary line in the drawer; the summary stays in tooltips.
